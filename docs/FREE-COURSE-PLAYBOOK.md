# Плейбук: бесплатный курс-лидмагнит на Stepik

Воспроизводимый процесс, отработанный на трёх курсах: 183103 («Собеседование в
маркетинге»), 183097 (добавлен видео-урок «Профессия таргетолог»), 297305
(«Маркетинговая аналитика»). Каждый такой курс — бесплатная воронка в платный
курс 94834 («Интернет-Маркетолог: Старт Карьеры»).

## Вход от пользователя

Обычно достаточно одной фразы вида «сделай курс по X, вот референс». Дальше
нужно уточнить (через AskUserQuestion, не гадать):

1. **Масштаб** — короткий курс-тизер (3-4 модуля, ~1.5 часа, как «Собеседование»)
   или полноценный курс (5-7 модулей, 2-8 часов, как «Таргетолог»/«Аналитика»).
2. **Воронка** — funnel в 94834 по промокоду `CAREERSTART` в конце (стандарт)
   или курс самостоятельный.
3. **Реальные данные** — если тема позволяет, использовать реальные цифры
   пользователя (сейчас источник — GA4 cleanor.app, property 528540338, через
   `mcp__analytics-mcp__run_report`) вместо выдуманных примеров. Спросить, а не
   решать за пользователя — это ощутимо больше исследовательской работы.

Референсный курс (если дан) — только ориентир по охвату тем/структуре,
никогда не копировать формулировки.

## Порядок действий

### 1. Исследование донора (ДО написания скелета)

Прогреп `stepik-sync/94834/raw/` по ключевым словам темы. Для каждого найденного
куска донорского контента отметить: **переиспользовать/сократить** (сильный,
готовый материал) или **явный пробел** (тема, которую в 94834 не раскрыли —
это то, ради чего вообще стоит делать бесплатный курс: закрыть недостающее
и одновременно быть качественной воронкой). Пример из курса про аналитику:
настройка Яндекс.Метрики и модели атрибуции — сильный переиспользуемый донор;
Google Analytics 4 и сводные таблицы — открытый пробел, писать с нуля.

Если решили использовать реальные данные — вытянуть их через
`mcp__analytics-mcp__run_report` (или `~/Developer/Web/cleanor-web/scripts/fetch-gsc.mjs`
для Search Console) **до** написания текста уроков, а не после — прозу проще
подгонять под уже известные цифры, чем наоборот.

Донорский текст почти всегда содержит устаревающие детали — конкретный год
(«в 2024 году»), цены, названия площадок, курсы валют. При адаптации это
нужно либо снять («в последние годы» вместо конкретного года), либо
проверить и обновить, а не копировать вслепую — иначе свежий бесплатный
курс на старте несёт устаревшие факты.

### 2. Создание курса

```
POST /api/courses  {title (≤64 симв.), language: "ru", is_paid: false}
```
Обязательны только `title` и `language` (проверено через OPTIONS). Сразу
после создания — заполнить `summary`, `description` (хук → credibility →
блок «Что дальше» с CTA на 94834 и промокодом), `target_audience`,
`requirements`, `acquired_skills` (массив строк), `learning_format`, `workload`.
Взять за основу формулировки уже готовых курсов 183103/297305 — стиль
устоялся, не изобретать заново. Следить, чтобы `description`,
`target_audience`, `requirements` и `acquired_skills` не повторяли друг
друга — это четыре разных блока на странице курса, и студент видит их один
за другим: если «Чему вы научитесь» дословно пересказывает то, что уже
сказано в «О курсе», это не выглядит как более длинный курс, это выглядит
как вода. Если воронка на `CAREERSTART` — проверить `GET
promo-codes?course=94834`, что код ещё не истёк, прежде чем на него ссылаться.
`workload` считать, а не угадывать: количество контентных уроков × 5-8 минут
на чтение + 10-15 минут на тест каждого модуля — так ожидание студента по
времени совпадёт с реальностью, а не окажется заниженным или завышенным.

**Готча:** новый курс не обязательно приходит `is_public: False` — 297305
оказался сразу публичным. Проверять явно. Если нужно скрыть уже публичный
курс, `PUT` может вернуть `400 "...basic_paid функции... не может быть
опубликован как basic"` — это ограничение тарифного плана аккаунта Stepik,
не чинится через объект курса. В этом случае просто сообщить пользователю.

### 3. Скелет

Скопировать `scripts/build_183103_skeleton.py` → `build_<course_id>_skeleton.py`.
`SKELETON` всегда одной формы:

```
Старт: [Видео-приветствие, Что будет на курсе]
Модуль 1..N: [Что будет в модуле «X», 2-4 контентных урока, Проверка знаний: X]
Что дальше: [Итоги курса, Продолжите обучение]
```

Скрипт создаёт секции + пустые уроки (`steps: []`) и сохраняет id в
`_<course_id>_skeleton_created.json`.

**Готча:** `Lesson.title`, как и `Course.title`, ограничен 64 символами —
POST падает с `400 Bad Request` без внятного объяснения, какое именно
поле виновато. Проверять длину заголовков заранее (`len(title) > 64`), а не
узнавать по факту падения скрипта на середине — при падении часть секции
уже создана, и придётся дописывать оставшиеся уроки вручную, ориентируясь
на реальный `GET sections/{id}`, а не пересоздавать с нуля.

Сразу после — короткие описания модулей (`sections.description`, ≤1000
симв., по 1-2 предложения) через GET-modify-PUT на каждую секцию. Лёгкий шаг,
но забывается — делать сразу, не откладывать.

### 4. Визуал

**Шапки** — `scripts/gen_183103_headers.mjs` как образец →
`gen_<course_id>_headers.mjs`. Одна запись на урок (кроме видео-приветствия):
`{lesson, label, title}`. Конвенция label: интро модуля — `«НАЗВАНИЕ МОДУЛЯ ·
МОДУЛЬ»`, контентный урок — `«... · УРОК N»`, тест — `«... · ПРОВЕРКА ЗНАНИЙ»`.
Рендер: `render_batch.mjs <html_dir> <png_dir> 1920 420` → `cwebp -q 82` →
`stepik_upload_attachment.py <course_id> <file>`.

**Иконки** — `scripts/push_lesson_icons.py <mapping.json>`, полностью
переиспользуемый без изменений. `mapping.json` = `[{lesson_id, icon}]`, где
`icon` — имя из набора Flat Color Icons (список: `GET
https://api.iconify.design/collection?prefix=flat-color-icons`, 329 иконок).
Подбирать по смыслу урока; для интро-уроков и тестов можно переиспользовать
одну иконку по всему курсу (например, `approval` для всех тестов) — это
осмысленный паттерн, не халтура. Работает и для видео-урока — единственный
рабочий способ поставить `cover_url` (см. готчу ниже).

**Графики по реальным данным** (когда есть реальные цифры и они — суть
урока) — `scripts/gen_297305_charts.mjs` как образец. Никакой chart-библиотеки:
обычные `div` с инлайн-шириной/высотой в процентах, класс `.banner-a` (чтобы
`render_batch.mjs` подхватил через тот же селектор), брендовые цвета из
`BRAND`/`fontFaceCss()` (`slide_template.mjs`). Стоит делать только когда
график реально доносит мысль быстрее таблицы (сравнение каналов, тренд,
распределение) — не на каждый урок.

### 5. Контент уроков

Формат каждого контентного урока: шапка `<img>` первой строкой → «Что будет
на уроке?» → 250-350 слов по существу (сокращённый донор или новый текст на
пробел) → «Что дальше?» (переходная фраза, см. готчу) → «Полезные ссылки»
(2-3 реальные ссылки, **обязательно проверенные curl** — предпочитать
официальные справки Google/Yandex/Microsoft и известные стабильные
инструменты над блог-постами).

Пуш: `scripts/push_text_step.py <lesson_id> <html_file>`.

**Тесты**: `scripts/create_choice_steps.py <lesson_id> <questions.json>
<intro_html>` — 10 вопросов × 4 варианта × 1 правильный, вопросы должны
проверять именно то, что было в написанных уроках этого модуля, а не общие
факты.

**Планка полезности.** 250-350 слов сами по себе ничего не гарантируют —
можно написать 300 слов общих рассуждений и не дать студенту ничего, что
применимо на практике. В каждом контентном уроке должен быть минимум один
конкретный, самостоятельно ценный элемент:

- цифра или формула с реальным расчётом («CPA = 5000 ₽ / 25 заявок = 200 ₽»,
  а не просто «CPA — это стоимость действия»),
- контраст хорошо/плохо на конкретном примере (не «пишите résюме грамотно»,
  а рядом стоящие хороший и плохой варианты одной фразы),
- чек-лист или пошаговая инструкция, которую можно взять и применить сразу,
- реальные данные вместо придуманных, если тема это позволяет (см. раздел
  про графики выше).

Если урок после первого черновика состоит только из абзацев-рассуждений без
единого такого элемента — это сигнал переписать, а не сигнал добавить ещё
абзац.

**Не каждый курс обязан заканчиваться воронкой в 94834.** Курс 183079 (вайб-кодинг) — первый, где тема не про маркетинг: финал там без CAREERSTART, просто итоги и призыв начать свой проект. Решение о финале — та же клариф-вопрос, что и про масштаб, не дефолт.

**Не каждый курс имеет донора в 94834.** Если тема генуинно новая (как вайб-кодинг), шаг 1 плейбука («исследовать донора») просто даёт «донора нет» — это не повод пропускать проверку, реальный ответ иногда и есть «пишем с нуля», и это нормально.

**Опциональный блок «Готовые промпты».** Если тема курса — работа с AI-инструментом (не обязательно кодинг), вместо/в дополнение к «Полезные ссылки» можно завершать урок 2-4 готовыми промптами по теме урока, которые можно скопировать и сразу вставить в диалог с агентом. Это прямой ответ на частую жалобу на курсы без письменного конспекта («смотрел видео, не смог вспомнить формулировку потом»).

### 6. Проверка перед сдачей (всегда, без исключений)

Выгрузить все уроки+степы через API одним проходом и проверить
программно:
- сбалансированность HTML-тегов
- ровно 4 варианта / 1 правильный в каждом choice-степе, без дублей текста
- нет `example.com`, нет смешения латиницы/кириллицы в словах
- у каждого текстового урока есть шапка, у каждого урока — `cover_url`
- `is_draft: False` везде
- количество слов на текстовый степ (быстрый `re.sub('<[^>]+>', ' ', text).split()`)
  — уроки заметно короче остальных в том же курсе стоит открыть и
  перечитать на «планку полезности» из раздела 5, а не просто зафиксировать
  цифру

**Затем — вручную вычитать каждую фразу «Что дальше?»** и сверить с реальным
порядком юнитов в секции (`GET sections/{id}` → `units` → позиции). Это
самая частая реальная ошибка на практике: контент пишется урок за уроком, и
если порядок уроков в скелете при планировании отличается от порядка,
который подразумевает сам текст (кто на что ссылается, что уже "было
пройдено" по смыслу), связки рассинхронизируются. Ровно это произошло в
курсе 183103 — «Тестовое задание» был запланирован после «Встречи с
нанимающим менеджером», хотя текст самой встречи уже предполагал, что
тестовое пройдено раньше. Пришлось переставлять юниты, перегенерировать 3
шапки с новыми номерами уроков и переписывать 4 переходные фразы. Дешевле
сверить порядок один раз в конце, чем чинить постфактум.

## Известные грабли

- **`cover_url` не заблокирован**, вопреки более ранним выводам. Он
  принимает только `ucarecdn.*` домены, но `ucarecdn.stepik.net` — не
  единственный: публичный неаутентифицированный endpoint Uploadcare
  (`https://upload.uploadcare.com/base/`, ключ `demopublickey`, без
  регистрации) отдаёт `ucarecdn.com/<uuid>/...` — тот же Uploadcare, другой
  домен, и Stepik принимает такую ссылку идентично. Это открывает
  программную установку иконок для ЛЮБОГО курса — руками через редактор
  больше заливать не нужно.
- Iconify отдаёт 403 на дефолтный User-Agent urllib — всегда передавать
  реальный (`curl/8.0` достаточно) при запросе SVG.
- Новый курс не гарантированно приватный после создания — проверять
  `is_public` явно, не полагаться на дефолт.
- Разжалование уже публичного курса обратно в приватный может упереться в
  `400 basic_paid` — тарифное ограничение аккаунта, не факт курса.
- Реальные данные (GA4 через `mcp__analytics-mcp__run_report`) делают уроки
  на порядок убедительнее выдуманных цифр — но тянуть их нужно ДО, а не
  после написания текста.

## Переиспользуемые скрипты (все в `scripts/`)

- `stepik_push.py` — OAuth-токен + `api_get`/`api_post`, импортируется всеми остальными
- `stepik_upload_attachment.py` — загрузка файла как course attachment
- `push_lesson_icons.py` — весь пайплайн иконок (Iconify → PNG → Uploadcare → cover_url)
- `push_text_step.py` — создать текстовый step-source на пустом уроке
- `create_choice_steps.py` — intro-степ + N choice-степов теста
- `render_batch.mjs` — общий Playwright HTML→PNG рендер (селектор `.banner-a`/`.frame`/`.igsh-frame`)
- `slide_template.mjs` — `BRAND`, `fontFaceCss()`, общие CSS-компоненты слайдов
- `gen_297305_charts.mjs` — образец графика по реальным данным без библиотек
- `build_<id>_skeleton.py`, `gen_<id>_headers.mjs` — per-course, копировать самый свежий (297305) как шаблон

## Loom-видео приветствия

Отдельно от контента: `scripts/presentations/loom-intro-<course_id>/build.mjs`
(копировать `loom-intro-297305`) — короткая презентация (6-8 слайдов: титул,
автор, для кого, программа по модулям, [опционально] что отличает курс,
как проходить, финал с промокодом) для показа поверх записи в Loom. Все
подписи на слайдах — для зрителя, никаких служебных пометок вроде «для
записи в Loom». Плюс отдельный текст-скрипт для самой начитки (не слайды):
хук на реальной боли без «вы наверняка уже знаете», честная (не
утешительная) постановка проблемы, credibility одной фразой, разбор по
модулям, закрытие без нажима.
