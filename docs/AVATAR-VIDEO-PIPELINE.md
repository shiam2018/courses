озвучку аватаром HeyGen.

существуют, в них только нет нормального контента.

## Чем это отличается от `loom-detailed-*`

Комплекты `loom-detailed-baza`, `loom-detailed-instrumenty` и остальные это
подробные конспекты для чтения: по странице на каждый шаг урока, 32-94
страницы, экспорт в PDF. Их читают.

Видео-комплекты другие: 13-15 слайдов на модуль, минимум текста на слайде,
потому что текст произносит аватар. Одно другому не мешает, PDF остаётся как
материал для чтения.

## Зона аватара

Шаблон `scripts/video_slide_template.mjs` резервирует правый нижний угол
(`AVATAR_SAFE_W/H`, 420x420 в координатах 1600x900). Контент туда попадать не
должен, иначе аватар его перекроет.

Проверять глазами ненадёжно, поэтому есть скрипт:

```bash
python3 scripts/check_avatar_safe_zone.py scripts/presentations/<папка>/out
```

Он сравнивает пиксели в зоне с фоном слайда и падает, если находит контент.
На практике ловится один и тот же случай: сетка из шести карточек в два ряда,
нижний ряд уходит под аватара. Лечится заменой на список или сокращением
подписей. Все шесть комплектов проверку проходят.

## Пересборка

```bash
cd scripts/presentations/<папка> && node build.mjs
cd ../.. && node render_batch.mjs presentations/<папка>/out presentations/<папка>/out 1600 900
python3 check_avatar_safe_zone.py presentations/<папка>/out
```

PNG не коммитятся (`.gitignore`), они пересобираются из `build.mjs`.

## Сборка видео и заливка

1. HeyGen: слайды из `out/` как фон, текст из `script.md` блоками по слайдам,
   аватар кружком в правом нижнем углу. Смена слайда должна совпадать с
   переходом к следующему блоку текста.
2. Заливка:

```bash
python3 scripts/upload_lesson_video.py <lesson_id> путь/к/видео.mp4
```

Скрипт делает `POST /api/videos` с полями `source` и `lesson`, потом опрашивает
Stepik, пока идёт транскодирование.

**Важно:** загрузка в урок, где видео уже есть, добавляет второе, а не заменяет
первое. У четырёх модулей лежат старые заглушки на 35-65 секунд, их надо
удалить руками через редактор Stepik после заливки нового видео.

## Правила текста начитки

Те же, что и для остального контента проекта: никаких длинных тире, никаких
декоративных эмодзи, обращение на «вы», короткие предложения. Плюс специфика
озвучки: не писать «в этом уроке мы рассмотрим», не обещать трудоустройство в
модуле «Работа», не давать пафосных финалов.

Темп для расчёта хронометража: 130 слов в минуту.
