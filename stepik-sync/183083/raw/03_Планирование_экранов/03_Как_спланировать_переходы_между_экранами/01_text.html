Что будет на уроке?

Набор экранов сам по себе ничего не значит без продуманных переходов между ними — именно переходы определяют, легко ли пользователю найти нужное действие.

Как спланировать переходы за три шага:

  1. Определите главный экран — тот, что пользователь видит первым при каждом открытии приложения (обычно это список или лента)
  2. Постройте путь к ключевому действию — сколько нажатий требуется от главного экрана до совершения главного действия приложения (добавить задачу, сделать заказ, оставить запись)
  3. Продумайте путь назад — как пользователь возвращается к предыдущему экрану, не теряя контекст (например, не сбрасывая заполненную форму при случайном нажатии «назад»)

Хорошо / плохо: приложение, где для добавления новой записи нужно пройти через настройки, затем через отдельный раздел, затем найти скрытую кнопку — заставляет пользователя удалить приложение раньше, чем разобраться в интерфейсе. Приложение, где кнопка главного действия видна сразу с первого экрана — не заставляет искать, как выполнить основную задачу.

Частая ошибка: копировать структуру навигации известного крупного приложения (например, соцсети) для совершенно другого по смыслу простого приложения. Структура навигации должна следовать из вашего конкретного главного сценария, а не из привычки пользователей к чужому интерфейсу.
