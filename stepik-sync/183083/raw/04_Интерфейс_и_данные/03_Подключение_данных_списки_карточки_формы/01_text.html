Что будет на уроке?

Интерфейс без реальных данных — просто статичная картинка; данные превращают его в рабочее приложение.

Как обычно устроено подключение данных в конструкторе:

  • Источник данных — таблица (Google Sheets, Airtable) или встроенная база конструктора, где хранятся записи (товары, задачи, статьи)
  • Список или лента — настраивается так, чтобы автоматически показывать все записи из источника данных, а не быть вручную заполненным один раз
  • Детальная карточка — при выборе элемента списка подставляет данные именно этой записи, используя специальную настройку связи «показать данные выбранного элемента»
  • Форма — настраивается так, чтобы заполненные пользователем данные записывались обратно в источник данных, создавая новую запись

Хорошо / плохо: вручную вписать в дизайн экрана конкретные тестовые тексты вместо настройки реальной связи с источником данных — работает только для одной статичной демонстрации, но не станет рабочим приложением. Настроить экран на реальный источник данных с самого начала — сразу видно, как приложение поведёт себя с настоящими записями, включая пустые состояния и длинные тексты.

Частая ошибка: откладывать подключение реальных данных до самого конца работы над интерфейсом. Многие визуальные проблемы (переполнение текста, обрезанные изображения) становятся заметны только с реальными, а не «идеальными» тестовыми данными — лучше увидеть их раньше, а не после того, как весь дизайн уже утверждён.
